# Server Conventions

> Rules for `packages/server`: database, repositories, services, HTTP API and server errors. `architecture.md` covers package boundaries. `component-conventions.md` covers names, files and classes. `testing.md` covers tests.

## Layout

```
packages/server/src/
  index.ts             re-exports only
  server.ts            Server: opens the database, the services, the API and the runner listener
  client.ts            createApiClient and ApiError, bundled into the browser
  db/
    client.ts          openDb, Db
    schema/<table>.ts  one file per table, barrel in index.ts
    schema/shared.ts   shared column builders
    repositories/      one class per table, createRepositories.ts (createRepositories, inTransaction), the shared SQL
                       conditions (dispatchRule.ts, ownedBy.ts, runLabel.ts, runnerAuthority.ts), index.ts (re-exports only)
    migrations/        generated by drizzle-kit
  auth/                Better Auth, its routes and its config from the environment
  services/            one <domain>Service.ts per domain, createServices.ts, serviceError.ts, index.ts (re-exports only); nothing else
  api/                 contract.ts (oRPC contract), router.ts, app.ts (Hono host), errorInterceptor.ts, runEventStream.ts
                       (a run stream as an oRPC event iterator)
  controlPlane.ts      the ControlPlane for runners
  planeErrors.ts       classifiedPlane: a database outage as `unavailable`, an unexpected error as `internal`
  leaseTimes.ts        the lease length and the sweep interval, from the environment
  runnerAccess.ts      the refusal texts of a revoked runner and of a retired key
  relays.ts            Relays: the SSH relays between `halinka ssh` and the runner of a run
  runSshPath.ts        the URL path of the SSH relay of a run
  connectedRunners.ts  ConnectedRunners: the commands of the connected runner processes
  githubApi.ts         the calls to the GitHub REST API
  runBus.ts            RunBus and inRunTransaction: signals to the run streams that a run changed
  runEnd.ts            rules that the ControlPlane, the sweep and the services share for ending a run
  runRefusals.ts       the refusals of a finished run that RunService and PushService share
  pushLease.ts         the push checks and the stored push that the ControlPlane and PushService share
  deletion.ts          the deletes of a run that the ControlPlane and the services share
  waitReason.ts        why a queued run waits
  runStream.ts         RunStream: the changes of one run for one client
  watchRun.ts          the run stream that the CLI and the portal share
  sweep.ts             the periodic sweeps: expired leases, lost agent tests, waiting runs, sandbox TTL, gone repos, old rows
  secrets.ts           SecretCipher (seal and open) and the place of each secret kind
  tokens.ts            newToken and newUserCode (hashOf is in @halinka/utils/hash)
  rateLimiter.ts       RateLimiter: requests per minute per client address, for HTTP routes and WebSocket upgrades
  withoutNulls.ts      withoutNulls: a row with each null field as undefined, for the output of a service
  testing/             setUpTestDb, createTestServer, FakeGitHub and the other test helpers; index.ts re-exports (testing.md)
```

- A module of the root holds one concern that the `ControlPlane` and the services share. A helper of one unit stays private in that unit's file, above its user (`component-conventions.md`, Helpers).
- The database stays in `packages/server/src/db`. Only the server opens it.

## Schema

- Name tables in plural snake_case: `workflow_runs`. Write columns in camelCase. `casing: "snake_case"` maps them.
- Use `integer().primaryKey().generatedAlwaysAsIdentity()` for ids. The protocol and the API use numeric ids.
- Use `createdAt()` from `shared.ts` on every table. A row that starts work, such as a step run, has `startedAt` instead. Use `updatedAt()` on a table whose rows change after insert.
- Use `timestamp({ withTimezone: true })` for every other time column.
- Name every index and unique constraint:
  - Index: `<table>_<columns>_idx`, for example `step_runs_workflow_run_id_step_id_idx`.
  - Partial index: `<table>_<condition>_idx`, for example `workflow_runs_queued_idx`.
  - Unique constraint: `<table>_<columns>_unique`.
- Take the values of an enum column from the `as const` array of `protocol` when the protocol has it.
- When code outside the schema needs a row type or an enum value type, export it next to the table: `export type DbWorkflowRun = InferSelectModel<typeof workflowRuns>`, `export type DbWorkflowRunStatus = (typeof workflowRunStatus.enumValues)[number]`.
- Type each `jsonb` column with `$type<T>()`.
- Do not use `relations()`. Write joins in the query.

## Migrations

- Change the schema, then run `pnpm db:generate --name <what_changed>`. Do not edit a migration after you commit it.
- `openDb` applies the migrations when the server starts. Self-hosted PGlite needs this.
- `pnpm db:migrate` and `pnpm db:studio` use the database of `halinka start`. `dbLocationFromEnv` in `db/client.ts` finds it for both. PGlite allows one process: stop `halinka start` before you use them on a PGlite folder.
- To rename an index or a constraint, edit the generated migration before you commit it. Use `ALTER INDEX ... RENAME`, so the index is not built again.

## Repositories

- One class per table: `class WorkflowRunRepository { constructor(private readonly db: Db) {} }`. `Db` is the client or a transaction. Tables that are always written together share one class: `WorkflowRunEventRepository` writes events and their batches.
- Get repositories from `createRepositories(db)`. Do not call `new XRepository(db)` outside the factory.
- A repository does not call another repository and does not open a transaction. A service or the control plane does.
- A method does one thing. A service or the control plane puts the steps of a domain rule in sequence.
- A `find*` method or a conditional write returns the row or `undefined`. A `has*` method returns a `boolean`. A write with no result returns nothing.
- `create` inserts and `save` upserts; both take a `NewX` input type: `create(run: NewWorkflowRun)`.
- A boolean column keeps its name. A repository input gives it the `is`, `has` or `can` name and maps it to the column: `create({ isTestRun })` writes `testRun`. A service maps a `Db*` field to the API name: `isTestRun: run.testRun`.
- A repository takes the time from the database with `` sql`now()` ``. It does not take a `now` parameter.
- A repository returns `Db*` rows, with `null` in a nullable column. A service converts each nullable field to `undefined` with `withoutNulls`; the output schema of the procedure selects the public fields.
- Throw an `Error` only for a state that cannot occur, for example an insert that returns no row.
- Annotate a method that returns full rows with the `Db*` row type.
- Name a method after the domain action: `claim`, `requeue`, `finish`. Use `findById` and `findBy<Column>` for reads that can return `undefined`.
- When a method must run in a transaction, say so in one comment line that starts with `// Call it in a transaction`.

## Transactions

- Use `inTransaction(db, (repositories) => ...)`. Every repository in the callback writes in the same transaction.
- Keep a transaction short. Do not call a runner command or other I/O inside it.
- Every `ControlPlane` write about a held run checks its lease in the transaction of the write (`architecture.md`, rule 8). `sync` finds the runs of its process by `lease_holder` instead.

## Services

- One class per domain in `services/<name>Service.ts`: `RepoService`, `RunService`. Get them from `createServices({ db, connectedRunners, bus, localRunnerId, cipher })`.
- `createServices` builds the repositories once and gives each service what it needs in the constructor, as positional parameters (at most 3, then an options object: `component-conventions.md`). A field of a service has the name of its key in `createServices`. A service that opens a transaction also takes `db`.
- Put domain logic in services: validation that needs the database or a runner, runner reads, and multi-table writes.
- A service method that compares times takes `now: Date` as a parameter, so a test can set it. `now` goes directly before `signal`, or last when there is no `signal`.
- Return database rows with their nullable fields converted to `undefined` (Repositories). The output schema of the procedure shapes them.
- The `ControlPlane` is not a service. Its shape comes from `protocol`.
- Write a run in `inRunTransaction(db, bus, (repositories, changed) => ...)` and report each change with `changed(workflowRunId, "events" | "state")`: `"events"` for new run events, `"state"` for the run's status, step runs or attempts. The helper sends the `RunBus` signals after the commit, and a run stream reads the change itself.
- Services do not import oRPC or `api/`. A service gives a stream as a plain object with `next()` and `stop()`; `api/` wraps it in an oRPC event iterator.

## Errors

- Throw `ServiceError` for an outcome that the client must see, for example `BAD_REQUEST`, `NOT_FOUND`, `INVALID_WORKFLOW`, `RUNNER_OFFLINE`.
- Write one factory in `serviceError.ts` for each `ServiceError` that two or more places throw: `noRun(id)`. Do not copy its message.
- A refusal is a `ServiceError` value. The text that explains it is a `*Reason`: `revokedReason`.
- A test asserts an error by its `code`, not by its message (`testing.md`).

## HTTP API

- oRPC, contract first. `api/contract.ts` defines every procedure: its REST route, the errors it can throw, its input schema and its output schema. The portal bundles the contract: it imports at run time only `zod`, `@orpc/contract`, the roots of `protocol` and `workflow`, and `@halinka/utils/repoFiles`, and only types from the rest of the server.
- Give every procedure an `.output` schema. oRPC runs it and removes the fields that are not in it, so a database row never goes out as it is. Do not write mapping functions.
- An output gives "no value" as an absent field (`.optional()`). An input that changes a value takes `null` to clear it, and an absent field keeps it: `allowedAgents: null` is every agent, `githubRepoId: null` deletes the link.
- `api/router.ts` implements the contract. A handler only calls one service method with the input. The method has the name of the procedure.
- `api/app.ts` mounts the `OpenAPIHandler` in Hono at `/api`. Hono stays the host for routes that are not procedures, such as webhooks and OAuth.
- A `ServiceError` code is an error of the contract (`apiErrors`), with its status. A procedure declares the codes it can throw with `.errors(errors(...))`. `api/errorInterceptor.ts` changes a `ServiceError` into that `ORPCError`, also in an event stream, and logs a `ServiceError` that the procedure does not declare and every unexpected error. The body is `{ defined, code, status, message, data }`. An input that does not match the schema answers `BAD_REQUEST` with `data.issues`.
- Callers use `createApiClient` from `@halinka/server/client`. A failed call throws `ORPCError`; `isDefinedError` narrows `data` to the type in the contract.

## Tests

`testing.md` has the test rules. Server tests also follow these rules:

- Call `const testDb = setUpTestDb()` once at the top of a test file. It opens one PGlite for the file and empties every table before each test, so ids start at 1.
- Use `createTestServer(testDb())` for API and control plane tests. It connects a fake runner.
- Use real repositories from `createRepositories(testDb())`. Do not mock repositories or services.
- Write data through repositories or the API. Change a row directly with `db.update` only to set up a state that no API can make yet.
